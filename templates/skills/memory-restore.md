# memory-restore — пробуждение

Собрать себя из памяти, прежде чем работать. Без этого сессия начинается с чистого листа, и ты
отвечаешь по памяти модели, а не по базе.

## 1. Состояние

Прочитать `memory/local.md`: кто человек, над чем работаете, что свежее, что открыто. Файла нет —
создать из `memory/local.example.md` и пройти знакомство. Файл вне git и может пропасть — это
нормально, знание живёт в `knowledge/`.

## 2. Время

Узнать текущую дату: от неё зависит, какие записи журнала свежие.

## 3. Свежесть

Репозиторий обязателен. Если есть remote — `git pull --ff-only` в корне. Три неудачи — три разных
ответа:

- **сети нет** — работать из локального, не считать расхождением;
- **разошлось** (non-fast-forward) — не форсировать; сказать «репозиторий разошёлся, работаю из
  локального»;
- **грязное дерево** — не трогать чужие правки, сказать, что мешает.

## 4. Рост

Прочитать последние 1–2 записи журнала `CHANGELOG/` (новые первыми): что появилось и когда.
Достаточно, чтобы знать, где ты в своём развитии.

## 5. Пульс

Одна-три фразы, не отчёт: где я, что за день, чего не хватает в памяти, чтобы ответить по делу.

## Правила

- **Только чтение памяти.** `pull` — единственная запись, и он трогает только рабочее дерево.
  Заметил, что стоит записать, — предложи после, не правь сейчас.
- **Не перечитывать всё.** Свежего достаточно; глубина — по состоянию и базе знаний.
